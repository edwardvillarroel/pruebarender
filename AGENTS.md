# AGENTS.md

ApoloVibes: web store for 3D-printed products with LLM-assisted custom designs. Monorepo: Flask backend at repo root (`app/`), React frontend in `ApoloVibes-frontend/`. All code, comments, and docs are in **Spanish** (entities, routes, error messages); write new code in Spanish to match.

## Governance

- `docs/ARQUITECTURA.md` (duplicated at root as `ARQUITECTURA.md`, byte-identical; edit `docs/`) is the design contract. The API contracts in §6 are **imposed by the already-built frontend** — do not change route shapes, field names, or response formats without updating the frontend.
- **Mandatory Clean Architecture layering** (ARQUITECTURA §3.1):
  - `app/domain/` — pure Python, no Flask/SQLAlchemy.
  - `app/application/` — use cases depend only on `domain` via interfaces (DI); application modules must never import each other (DTOS live in `application/common/dto.py`).
  - `app/api/` — routes/middleware, depends on `application` + `domain`. **`app/api/routes/auth_routes.py` is the one existing violation** (it imports `UsuarioModel` from infrastructure directly) — do not copy that pattern into new endpoints.
  - `app/infrastructure/` — implements `domain` interfaces (repositories, ORM models, LLM client, Celery).
- Two parallel entity sets mapping the same tables: pure entities (`domain/entities/`) and ORM models (`infrastructure/database/models/`). The ER model (9 entities) is fixed; keep both in sync.

## Backend commands

Run from repo root, in a venv, deps from `requirements.txt` (pinned, no lockfile):

1. `docker compose up -d db` — PostgreSQL 16 only (db `print3d_dev`, user/pass `app`/`app`). Redis/Celery are in requirements but have **no compose service**; LLM async task infra is not runnable via compose yet. To sanity-check the DB: `docker exec print3d_db pg_isready -U app -d print3d_dev` (fails if Docker/db isn't up).
2. `cp .env.example .env` and edit `SECRET_KEY`/`JWT_SECRET_KEY`.
3. `flask --app app run --port 4000` — must pass `--port 4000` explicitly; `config.py` never reads `PORT`. Frontend proxy and API base URL (`http://localhost:4000/api`) depend on this port.
4. Tests: `python -m pytest` from root. Fixtures (`app`, `client`) in `app/tests/conftest.py` use `TestingConfig` → `TEST_DATABASE_URL` (`print3d_test`), so tests need Postgres up. There are currently **no real test files** (only `__init__.py` skeletons under `app/tests/` + `conftest.py`). No pytest.ini/lint/typecheck config exists.

## DB / Oracle quirks

- `db` is SQLAlchemy() instantiated in `infrastructure/database/connection.py` and **is** `init_app`-ed in `create_app()` (`app/__init__.py`).
- **No migrations**: Flask-Migrate has **no `Migrate(app, db)`** wiring and there is no `migrations/` dir, so `flask db ...` fails. No `create_all` call and no seed script exist. You must create tables (importing the model modules first) or add migrations yourself — currently there is no way to create the `usuarios` table or a first user.
- `models/__init__.py` is empty; a model is registered with Flask-SQLAlchemy only once its module is imported (e.g. `auth_routes.py` imports `usuario_model`, and that's the only model loaded at boot). Any model you query must be imported somewhere reachable.
- **Oracle support** (recent commit): if `ORACLE_DSN` + `ORACLE_PASSWORD` are set, `config.py` switches `DATABASE_URL` to Oracle Autonomous (oracledb, wallet mTLS via `ORACLE_WALLET_DIR`/`ORACLE_WALLET_PASSWORD`). Otherwise Postgres is used. All ORM models use the `UuidRaw` TypeDecorator (`connection.py`) for PKs — UUIDs as `RAW(16)` on Oracle, `LargeBinary(16)` on Postgres; entity `id`s are `uuid.UUID`.

## Current state (verify before assuming anything works)

- Backend bootstraps in `create_app()` (`app/__init__.py`): CORS (Flask-Cors, `CORS_ORIGINS` env) + JWTManager + `db.init_app` + error handlers (`{mensaje}` JSON, incl. 501 for `NotImplementedError`). If `ApoloVibes-frontend/dist` exists it's served under `FRONTEND_BASE_URL` (`/ApoloVibes3D-Frontend/`, with `/` redirecting there; `dist` does not exist right now); `/api/*` always returns JSON, never the SPA.
- **Auth is implemented and DB-backed** (no more hardcoded creds): `POST /api/auth/login` looks up `UsuarioModel` by `email` (accepts `username` too), verifies `bcrypt`, returns `{ access_token, user }`; JWT claims are `sub` (user id uuid), `rol`, `email` (no `username` claim anymore). `GET /api/auth/me` uses `sub`. `POST /api/auth/register` still raises `NotImplementedError`. **Gotcha:** nothing can insert users yet (see DB quirks), so login can't succeed end-to-end until schema + user creation exist. **TZ gotcha (resuelto solo para dev):** los `creado_en` de `USUARIOS` se sembraron con zona con nombre (`TIMESTAMP WITH TIME ZONE`), que el driver `oracledb` thin no decodifica (DPY-3022) y rompe login/ORM. Ya se reescribieron como offset numérico UTC (mismo instante); si se re-sembran filas con `CURRENT_TIMESTAMP` o zona nombrada, hay que repetirlo (script `corregir_tz_usuarios.py`, temporal).
- **Cart CRUD is implemented, persisted and DB-backed**: `POST /api/cart/items` (`{producto_id, cantidad}`), `GET /api/cart`, `PUT/DELETE /api/cart/items/<uuid:item_id>`, `DELETE /api/cart`. **Requiere sesión** (`@jwt_required` en todos): `usuario_id` = `sub` del JWT (FK `carrito.usuario_id` → `usuarios.id`). Layered (`domain/entities/carrito.py` → `application/carrito/gestionar_carrito.py` → `infrastructure/repositories/carrito_repository_bd.py` + `models/carrito_model.py` `CarritoModel`/`CarritoItemModel`), service injected via `app.config["CARRITO_SERVICE"]` in `create_app` so `api/` never touches infra (el in-memory `carrito_repository_inmemory.py` queda de referencia, sin uso). `producto_id` debe ser un **UUID real existente en `productos`** (FK); si no, `Agregar` devuelve 404 `{mensaje}`; `producto_id` no-UUID → 400. La tabla en memoria `carrito_repository_bd` hace rollback+relanza `IntegrityError` y la ruta lo traduce (patrón `api/` importa solo `sqlalchemy.exc`, no infra).
- **Catálogo (productos/categorías) is implemented, DB-backed and sin auth** (misma fase que el carrito): `GET /api/productos` (solo `activo=True`), `GET /api/productos/<uuid:id>` (404 `{mensaje}` si no existe), `GET /api/categorias`. ## API conventions (frontend expects these)

- Base URL `http://localhost:4000/api`; error responses must be `{ "mensaje": string }` (frontend `src/services/api.js` throws `err.mensaje`; on HTTP errors it falls back to `` `Error ${status} al llamar ${path}` ``).
- AI generation: `POST /api/ai/image-to-3d` (multipart field `imagen`) → `{ taskId }`; poll `GET /api/ai/image-to-3d/:taskId` every ~2s → `{ status: processing|completed|failed, modelUrl, error }` (status values match `EstadoTarea` in `domain/enums.py`).
- Payment: `POST /api/pago/crear` with body `{ items, total, cliente }` → `{ url, token }`; frontend auto-submits `token_ws` to `url`; `POST /api/pago/confirmar` with `{ token }`.
- LLM inputs must be sanitized for prompt injection before reaching the model (see `application/asistente_llm/validar_prompt.py`, `application/disenos_personalizados/sanitizar_input.py`).
